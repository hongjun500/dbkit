# dbkit 审查与整改计划（review0616）

## 目标
在不做大重构的前提下，完成“简单但规范”的收敛：
- 修复 `gormLogMode` 的大小写/非法值静默降级问题，并严格对齐 GORM 四级日志（Silent/Error/Warn/Info）。
- 统一日志策略为：默认标准库 `slog`，可选 `zap`，减少并行日志通道的不一致。
- 处理高风险项（DSN 脱敏、超时语义、初始化边界）并补齐基础测试。

## 审查结论（问题汇总）

### P0（高优先）
- `gormLogMode` 输入大小写敏感，`INFO`/`Warn` 等会误落入默认 `Silent`：[`J:/goProjects/dbkit/mysql.go`](J:/goProjects/dbkit/mysql.go)。
- 非法日志级别静默降级为 `Silent`，无显式报错或告警，排障成本高：[`J:/goProjects/dbkit/mysql.go`](J:/goProjects/dbkit/mysql.go)。
- DSN 日志“脱敏”仅截断长度，未真正隐藏密码，存在泄露风险：[`J:/goProjects/dbkit/logging.go`](J:/goProjects/dbkit/logging.go)。
- MySQL 连接阶段超时语义不完整：`dial_timeout` 主要约束后续 ping，无法完整覆盖 `gorm.Open` 阶段的连接阻塞风险：[`J:/goProjects/dbkit/mysql.go`](J:/goProjects/dbkit/mysql.go)。

### P1（中优先）
- 日志存在并行通道：连接生命周期日志走 `dbkit.Logger`，SQL 日志走 GORM 默认 logger，格式与 sink 不一致：[`J:/goProjects/dbkit/mysql.go`](J:/goProjects/dbkit/mysql.go)、[`J:/goProjects/dbkit/postgres.go`](J:/goProjects/dbkit/postgres.go)、[`J:/goProjects/dbkit/logger.go`](J:/goProjects/dbkit/logger.go)。
- zap 声称“可选”，但根模块直接依赖 `go.uber.org/zap`，与可选化目标不完全一致：[`J:/goProjects/dbkit/go.mod`](J:/goProjects/dbkit/go.mod)、[`J:/goProjects/dbkit/logzap/zap.go`](J:/goProjects/dbkit/logzap/zap.go)。
- 连接池参数边界未显式约束（如 `MaxIdleConns > MaxOpenConns`）：[`J:/goProjects/dbkit/config.go`](J:/goProjects/dbkit/config.go)。

### P2（低优先）
- `debug` 级别被映射到 `Info` 属合理别名，但缺少文档说明，易造成误解：[`J:/goProjects/dbkit/mysql.go`](J:/goProjects/dbkit/mysql.go)。
- 缺少针对日志级别解析与脱敏逻辑的表驱动测试：[`J:/goProjects/dbkit`](J:/goProjects/dbkit)。

## 方案设计（最小改造路径）

### 阶段 A：先修正确性与安全（必须）
1. 规范化日志级别解析：`TrimSpace + ToLower`。
2. 严格白名单：仅允许 `silent/error/warn/info`（可选兼容 `debug->info`），非法值返回错误（推荐 fail-fast）。
3. 重做 DSN 脱敏：掩码用户密码与常见 password 参数，避免明文泄露。
4. 明确并修正 MySQL 连接超时语义（默认值与覆盖范围）。

### 阶段 B：统一日志策略（建议）
1. 保持默认 `slog`；`zap` 通过 `logzap` 适配器注入。
2. 统一文档口径：业务日志与连接日志统一走 `dbkit.Logger`；SQL 日志策略显式说明。
3. （可选）将 GORM logger 适配到 `dbkit.Logger`，消除并行日志通道。

### 阶段 C：补齐约束与测试（必须）
1. 为日志级别解析新增表驱动测试（大小写、空白、非法值、`debug` 兼容）。
2. 为 DSN 脱敏新增测试（userinfo、query 参数、异常输入）。
3. 为连接池参数增加边界校验与回归测试。
